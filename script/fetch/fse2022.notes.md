# Notes on these files (written by script/fetch_benchmarks.sh)

**Source.** The benchmark of Shi, Xie, Li, Zhang, Chen and Li, *Large-Scale Analysis of Non-Termination Bugs in
Real-World OSS Projects*, ESEC/FSE 2022, https://doi.org/10.1145/3540250.3549129: directory `benchmark/` of
`https://github.com/FSE2022benchmarks/-FSE-2022-Termination` (AGPL-3.0) at commit
`d6fd271e5f0250d4a734678143e9621d8c8aaf4d`. The files are upstream's bytes except the two patched below.

**Patched by this repository at fetch time** (`script/fetch/fse2022.patch`):

- `recursion/Incorrect_Return_2_NT.cpp`, `recursion/Incorrect_Return_2_T.cpp` -- one line added at the top,
  `extern char __VERIFIER_nondet_char(void);`. Upstream calls the function without declaring it; C accepts an
  implicit declaration, C++ does not, so the upstream files do not compile as C++.

**Labels that are wrong for the program.** The `_T` / `_NT` in a name (and the `termination: true|false` line in each
file's header) is the authors' label, not an oracle. Two are wrong:

- `loop/Incorrect_Initialization_2_T.c` -- **does not terminate**, under integer and bit-vector semantics alike. Start
  with `matroska != 1` and choose `id == 1` in every inner iteration: `res = res_return() < 0` assigns the comparison,
  so `res` becomes 1 whenever `res_return()` returns a negative value, which it may do before `flag` reaches 100 and
  always does afterwards. The inner loop then exits with `res == 1`, `matroska` is unchanged, and the outer loop
  repeats forever. The authors' own Ultimate Automizer run in the repository's `Evaluation/` answers `FALSE(TERM)`.
- `loop/Signed_Overflow_Error_1_NT.c` -- **terminates** wherever `long` is wider than 32 bits (LP64) and under
  mathematical integers: `for (i = 1; i <= 0xFFFFFFFF; i <<= 1)` reaches `i = 2^32 > 0xFFFFFFFF` and exits. It loops
  forever only where `long` is 32 bits. The authors' Ultimate run with `--architecture 64bit` answers `TRUE`.

The same two labels are wrong in the translations `benchmarks/LTS/fse2022/` (see the note there).
