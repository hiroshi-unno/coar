# BTOR2 models

Word-level hardware models in BTOR2, read with `-p btor2`.

`simple/` holds small hand-written models, each exercising one rule of the format's semantics
(an initialization, a state without `next`, a constraint, a negated reference, an array, every
operator). **The verdict in a file name is the Hardware Model Checking Competition's**: `_sat`
means a bad state is reachable (unsafe), `_unsat` that none is (safe). That is the reverse of the
answer of the constraint problem the model is translated into. `justice_unsupported.btor2` has a
liveness property, which the frontend refuses.

`all_ops_unsat.btor2` and `all_ops_negative_sat.btor2` are generated by `gen_ops.sh` (in this
directory); do not edit them by hand. `benchmarks/BTOR2/gen_ops.sh --check` regenerates them and
runs `-p btor2` on both, comparing each answer with the verdict in its name.

`free_state_init_time0_sat.btor2` separates the two readings of a state that has an `init` but no
`next`: it is unsafe only if such a state is free at time 0 too, which is what the format's
definition says ("A state variable without associated next function is treated as a primary
input", Niemetz, Preiner, Wolf, Biere, CAV 2018) and what the reference simulator's witness
checker accepts.
